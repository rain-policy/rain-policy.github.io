Refine Actions If Needed

Adaptive Action Chunk Refinement
for Robot Manipulation

Robot manipulation does not require the same amount of action refinement at every decision. Direct policies produce executable actions quickly, while iterative generative policies spend more computation to correct them. A fixed refinement budget can provide too little correction in one state and more than is needed in another.

Selected real-robot rollouts · 3× source playback · silent loops

We propose Refine Actions If Needed (RAIN), which learns whether an action needs refinement and how many steps to use. ACT first proposes an action chunk. RAIN predicts how accurate the action would be after different numbers of refinement steps, then weighs the improvement against computation cost. It runs only the chosen steps; choosing zero executes ACT’s proposal directly.

RAIN achieves 66.6% success across eight simulation tasks and 72.5% across four real-robot tasks. Compared with three fixed refinements, it uses 26.6% fewer flow-matching evaluations and 15.7% less policy compute, with a similar success rate.

From Prediction to Selective Refinement

RAIN starts with an action that the robot can already execute. Before running the refinement model, it uses the observation, proposed action and prediction uncertainty to choose how much correction to apply.

Method

ACT proposes an action chunk. RAIN estimates how much refinement will improve it, chooses the number of steps, and runs those steps before executing the action.

  1. 01

    Propose an action

    ACT predicts an action chunk from the observation history, together with an estimate of its uncertainty.

  2. 02

    Choose how much to refine

    Using the observation and proposal, RAIN predicts the action error after different numbers of refinement steps and weighs it against their compute cost.

  3. 03

    Refine and execute

    Run the chosen number of refinement steps and execute the action chunk. With zero steps, use ACT’s proposal directly.

How is the refinement choice learned?

We jointly train ACT and the refinement model, then freeze them. Actions produced with different numbers of refinement steps are compared with expert demonstrations. A group of predictors learns the resulting action errors and uncertainty. Calibration sets the balance between accuracy, uncertainty and computation, while recent refinement choices help keep decisions consistent over time.

Simulation uses a 400/50/50 training, calibration and held-out split per task. On the real robot, fitting and calibration use the same 50 demonstrations per task.

Questions & Answers

How does RAIN choose the number of refinement steps?

RAIN predicts the action error and uncertainty for each possible number of steps. It combines these estimates with compute cost and recent refinement choices, then runs the selected number of steps.

What happens when RAIN chooses zero steps?

The robot executes ACT’s proposed action chunk directly.

How does the refinement amount vary across tasks?

Some tasks often use direct actions or one refinement step; others use more correction. For example, PushT and StackPyramid use three steps for 99.6% and 97.4% of decisions. The task-level chart above shows the full distribution.
